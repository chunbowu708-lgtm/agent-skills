# 简历分析提示词模板

对每份简历按以下维度分析。输入：岗位名 + 评估要点 + 简历文本。

## 输出（每份）

```json
{
  "姓名": "...",
  "判定": "强推|可推|待定|不推",
  "一句话理由": "...（≤25字，总览表用）",
  "判据": "...（待定/不推必填，强推/可推可省）",
  "推荐理由": "...（仅强推/可推）",
  "风险提示": "...（仅强推/可推，无则省）",
  "建议面试重点": "...（仅强推/可推）",
  "待定Action": "...（仅待定：你需要做什么才能定）"
}
```

## 行家直觉（不会写进教科书但决定成败）

这些是游戏公司招聘BP反复被业务面试官训练出来的痛感记忆：

### 读简历的顺序（不是逐字读）
1. **公司名+项目名**：信息量最大的信号。腾讯/网易/米哈游/ Funplus等知名公司 >>> 公司数量。具体项目名（王者荣耀/和平营地/完美世界项目）比"参与多款项目"有信息量十倍。
2. **岗位title变化路径**：是一直在同方向深耕，还是频繁跨行？"高级产品策划→社区产品负责人"是上升路径；"特效→特效→特效"是深耕；"产品→运营→产品→市场"是漂泊。
3. **年限 vs 经验密度**：10年经验但全是"参与"不如5年但有"独立负责"。看角色深度，不只看年数。
4. **量化产出**：有数字（DAU、下载量、增长率）>>> 纯定性描述。但要看角色——"团队产出X"vs"我负责产出X"。

### 立刻警觉的信号
- **"参与"通篇**：没有"负责""主导""独立"→ 执行层，扛不住从0到1
- **模板化经历**：多段经历描述几乎相同 → 复制粘贴凑数，实际深度存疑
- **一年一跳**：不是一票否决，但必须标出让业务知道
- **自我标榜空洞**："核心成员""主力负责"但无量化、无具体角色 → 警惕挂名
- **BOSS标的年限和简历对不上**：标"存疑"，不挑一个当真
- **工具清单很长但项目描述很短**：工具多≠会用，看项目里怎么用

### 看似合理但绝不会用的判断
- **关键词匹配=对口**："简历有UGC"≠做过UGC产品。区分"设计工具让别人创作"（产品侧）vs"自己用工具创作"（内容侧）
- **沉默=不会**："简历没提某技能"≠不会，实操常以别的词描述。"设计埋点+搭看板"就是数据产品实操，不必出现"数据产品经理"
- **年限=能力**：10年但全"参与"< 5年但有"独立负责"
- **大厂=强推**：大厂背景是信号但要看角色——大厂的"参与"不如小公司的"主导"
- **有数字=牛**：看数字背后的角色——"团队DAU 500万"vs"我负责的模块DAU从0到500万"

## 怎么想（资深面试官视角，不是关键词匹配）

你要像一个看过上千份简历的业务面试官，**追问的是"做成这事所需的底层能力，候选人有没有"，而不是"简历里有没有这个词"**。

- **关键词命中 ≠ 会**：简历写"主导过 UGC 编辑器优化"，要追问是**设计工具让别人创作**（产品侧/平台侧），还是**自己用工具创作内容**（内容侧/执行层）。前者才是产品经理经验，后者不是——哪怕都有"UGC"这个词。
- **关键词没提 ≠ 不会**：实操常以别的词描述。"设计埋点+搭数据看板"就是数据产品实操，不必出现"数据产品经理"这个头衔。**沉默信号不得单独判死方向。**
- **量化要看角色**：有数字不代表是 TA 做的。区分"我负责→产出X"和"团队产出X，我参与"。警惕自我标榜（"核心成员"可能挂名）。
- **深度超出文本可判时，落待定**：一份经历是"基础执行"还是"主导设计"，有时文本分不出来（尤其只有一句话带过的）。这时别硬判——落待定 + 标"深度存疑，建议业务确认"。

## 四个维度（按顺序，但方向不再一票否决中断后续维度）

### 维度1：方向匹配
候选人实际方向 vs 岗位方向。读评估要点的"硬卡项"里对方向的定义。
- 方向**严重不对口**（通篇无任何对口信号，纯跨行如 ERP 产品投 AI UGC 岗）→ 🔴不推
- 方向**看起来偏，但有任一真实对口经验**（哪怕一句话提到做了对口的事）→ **不要判死，落⚪待定**，注明"主线偏X但有Y对口信号，建议业务确认深度"。继续跑后续维度。

### 维度2：硬性项达标
逐条对照评估要点的硬卡项（学历、经验年限、特定技能）。
- 全达标 → 继续
- 有不达标但属"可放宽项" → 标注，倾向⚪待定
- 不达标且非可放宽 → 🔴不推 或 ⚪待定（视严重度）

### 维度3：项目含金量（核心区分项，决定强推 vs 可推）
看四点：量化结果、角色深度（负责/主导 vs 参与/协助）、项目规模/知名度、水分警惕（自我标榜是否空洞）。
读沉默信号：几年经验却只有学校项目、或全是"参与"没成果 → 不轻易给强推。

### 维度4：风险 + 加分
- **风险**（读评估要点"雷区"）：跳槽频率、经历断档、跨行跨度、短期经历扎堆。出现→不直接判死但必须标出，影响档位（强推降可推、可推降待定）。
- **加分**（读"秒推信号/加分项"）：命中秒推信号→托到强推；命中加分项→同档往上排。

## 判定落档（偏宽松，怕漏人）

| 情况 | 落档 |
|------|------|
| 方向**严重**不对口（零对口信号） | 🔴不推 |
| 硬卡项不达标且非可放宽 | 🔴不推 |
| 硬卡项有不达标但属可放宽 | ⚪待定 |
| 外部信号(BOSS届数/经验)与简历事实冲突 | ⚪待定 + 标冲突 |
| 方向偏但有对口信号 / 深度文本不可判 | ⚪待定 + 标"建议人工复核" |
| 方向对口+硬性达标+含金量足+【强推三道关全过】 | 🟢强推 |
| 方向对口+硬性达标但项目偏弱、有风险、或任一关存疑 | 🟡可推 |

**🔴不推的红线**：只在【方向零对口信号】或【硬卡不达标且不可放宽】时用。只要有一丝对口经验或可放宽空间，就不能判死——落待定让人看一眼。

### ⛔ 落档前自检清单（每份简历落档前必过，2026-07-30 新增）

> 教训：7.30 坤灵系统客户端 6 人，首轮 5 人全判🟡可推，理由里其实已点出陈墨"外围系统经验弱/方向错配"却仍给🟡——**理由和结论自相矛盾**。根因是"先有档位倾向再找理由圆"，不是从事实推档位。这份清单把落档从自由判断改成事实校验，专治理由结论矛盾 + 尺子量错东西。

**落任何档位前，逐条过（每条必须能指向简历原文事实，说不清就重判）：**

1. **结论←理由一致性**：把你写的"顾虑/亮点"重读一遍——结论（档位）是不是从这些理由**必然**推出？
   - 反例：顾虑写"两个核心项目都是战斗从零，外围系统几乎没碰" → 结论却给🟡可推（系统客户端岗）→ 矛盾，该降⚪待定（方向错配）。
   - 自检：如果理由成立但结论读着"偏高"，强制降一档或重写理由。

2. **量对了东西吗**：你用来定档的关键事实，是不是岗位**真正的区分维度**，还是个"近似物"？
   - 反例：系统客户端岗用"Unity年限"区分（6人里5个都够）→ 没区分度；该用"外围系统（养成/活动/商业化）实操深度"区分。
   - 自检：每个岗位先锁 1-2 个**真区分维度**（读评估要点的"真实看重什么"），用它们卡，别拿年限/学历这种全员达标的项当主尺。

3. **🟡可推 ≠ 默认档**：给🟡前必须答——"他和🟢强推差在哪一条具体事实上？"答不出（找不到差在哪）→ 要么升🟢要么说明他还不够🟢的具体短板。不许"都不错就给黄"。

4. **⚪待定必须可执行**：待定的 Action 不是"建议复核"，是"看什么具体事实/问什么具体问题就能定档"，且那个事实验证后**确实能改变结论**。

5. **🔴不推事实可溯源**：不推理由里每个事实，必须能在简历原文指出来（第几段写了什么）。有一条指不出 → 降⚪待定。

### 🟢强推三道必检关（落强推档前逐条过，任一存疑→降可推）

> 强推=可直接打包发业务，标准比"硬条件达标"更高。方向/硬卡/含金量/雷区全过只是入场券，还必过这三道关——它们专治"硬条件都达标但推过去业务还是不满意"的漏判。2026-07-17 一份报告连续五次下调档位（朱思奇/谭路/王健章/雷鹏飞换岗）换来的教训：规则早写在上面"看似合理但绝不会用的判断"里，但没收口到落档环节，评估时照样漏。

**1. 角色匹配关**：简历呈现的实际角色 = 岗位要的角色？
- 不是"简历有这个领域的关键词"，而是"ta在这个领域是策划/设计侧，还是执行/内容侧"。
- 典型漏判：UGC岗把"UGC内容创作者/用工具做内容的人"当成"UGC工具设计者"；商业化策划岗把"商业化运营/优化师"当成"商业化策划"。区分见上文"关键词命中≠会"。
- 过关标准：能一句话说清"ta在简历里是什么角色"，且这个角色正是岗位JD要的角色。

**2. 业务敢用关**：这个 profile 推给业务，业务会质疑"给我推这个干嘛"吗？
- 换位到业务面试官视角：看到这份简历第一反应是"对口"还是"这好像不太是我们招的"。
- 典型漏判：title 通篇是"运营"的人推给"策划"岗；纯执行背景推给要独立负责的岗。
- 过关标准：profile 的表面身份（title/主要经历）与岗位名称不产生明显违和，不需要 HR 费力解释。

**3. 团队接得住关**：候选人的资历/年龄/稳定性，与目标团队现状和岗位定位匹配吗？
- 0到1新项目：超资深/高龄候选人能不能接受从风格探索做起（而非带团队）？精力与学习曲线？
- 稳定性：跳槽频率（平均<2年）+ 最近一段任期是否过短。
- 过关标准：没有明显的"资历错配"或"稳定性红旗"，不需要业务额外操心融入问题。

> 三道关任一"存疑"（不是"不通过"，是"说不准/有顾虑"）→ 降🟡可推，并在顾虑里写明是哪道关、什么疑点。落强推档要在心里能坦然说出"这三道我都放心"。

## 横向对比（同岗位2人以上必做，2026-07-30 强化）

> 教训：7.30 坤灵系统客户端 6 人首轮 5 人🟡，等于没排序——业务最想知道的"先见谁、区别在哪"完全没答。同档扎堆=没区分=评估无效。

同岗位多人时，分析完每个人后**强制**产出：

1. **严格全序排序（不许并列，不许扎堆同档不做区分）**
   - N 个人必须排出 1>2>3>...>N 的完整名次，即使档位相同也要在同档内分先后。
   - **禁用"≈"批量并列**：除非两人简历几乎相同，否则一律分出高下。"宋家兴 ≈ 朱俊杰"这种写法只在两人确实难分时用，且仍要说明"难分在哪、各自强在哪"，不能当偷懒借口。

2. **相邻两人必须写一条区分事实**（排序的硬证据）
   - 格式："A > B，因为 A 做过【具体经历X】，而 B 没有 / B 只做到【较弱程度】"。
   - 区分事实必须指向简历原文，且和岗位区分维度直接相关。
   - 反例（无效）："A 比 B 经验更丰富"——空话。
   - 正例："宋家兴 > 陈天昊，因为宋家兴在卡牌项目做过排行榜/活动/邮件等外围系统实操，陈天昊自我定位 TA、冰川经历以工具链+优化为主、外围系统开发非主导"。

3. **业务先见谁 + 为什么**（必答，不是加分项）
   - 业务拿到简历一定问"帮我排个序""有什么区别"。
   - 如果只推荐一个先见，明确说谁、说理由（通常是"区分维度最对口的那条"）。

4. **风格差异 / 互补性**（同档或都通过时有价值）
   - 各自偏什么方向/能力类型；如果都通过，团队配置上是否互补。

> **同档人数熔断**：单个岗位同一档位（尤其🟡可推）超过 2 人时，强制重新用"落档前自检 #2 量对了东西吗"的区分维度再切一遍——多半是尺子没量对导致集体发牌。
