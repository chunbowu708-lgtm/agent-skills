# 面试时间协调

## 职责分工

```
用户给：面试官 + 候选人 + 可面试时间
AI 做：自然语言 → 脚本参数（无损转译）；处理脚本标注的【需问用户】缺口；按交付契约展示
脚本做：面试官空闲 ∩ 候选时间 → 会议室校验 → 完整草稿（措辞唯一事实源）
```

## 执行步骤

### 1. 确认三要素（缺一问用户，不猜）

| 要素 | 规则 |
|---|---|
| 面试官 | 用户口头给；昵称（Sava/海哥/Tina 等）可直接传，经 interviewers.json 的 alias 解析 |
| 候选人 + 可面时间 | 用户口头给 |
| 形式 | 默认 `--form 视频`；用户明确说"线下"才传 `--form 线下`（传"现场"自动归一化为"线下"） |

### 2. 查 talent_id

从 `<PROJECT_ROOT>/notes/_daily_review.json`（用前确认 `generated_at` 是今天）的 `structured.ats[*]` 按姓名查，传 `--talent-ids`（与 `--candidates` 条目顺序对齐）。

快照里没有（当天新录入/未录入）→ 构造临时 JSON 传 `--ats-file notes/_tmp_ats.json`（用完删）：

```json
{"structured":{"ats":[{"name":"姓名","talent_id":"","stage":"面试","job":"岗位","dept":"团队","interview_count":0,"latest_conclusion":null}]}}
```

### 3. 转译候选时间（转错=废稿，规则全在此表）

| 场景 | 传参 | 禁止 |
|---|---|---|
| 能确定语境 | 绝对日期 `8-3` | 丢模糊词给脚本猜：今天周一传"周一"会被解析成下周一 |
| 已过时段 | 现在是下午 → 从明天起传 | 传今天上午（拟安排会落在过去） |
| 候选人说"X点到Y点" | 区间 `8-20 14:00-15:00`（24h制） | 只传起点时刻——语义是"起点以后都行"，会建议出窗外时段 |
| 窗口表达 | 完整传：`8-5\|8-6\|8-7` | 为集中排布压缩窗口——窗口=候选人原话，只有拟安排可优化 |
| 多日期 | `\|` 分隔（逗号已用于分隔候选人） | — |
| 复杂窗口（"明天上午+工作日下午"） | 同名多条目：`李四=8-5上午,李四=8-6下午\|8-7下午`（talent-ids 传两次同值）；条目顺序=拟安排优先级 | — |
| "精确区间 ∪ 全天"（"今天2点到3点或明天全天"） | 单条目：`李四=8-20 14:00-15:00\|8-21` | — |

拟安排偏好（多安排某天/黄金时段）只靠条目顺序控制，不动窗口。

### 4. 跑脚本

```bash
# 标准：传 talent_ids 精确匹配 ATS（时长默认45分钟，需要60显式传 --duration 60）
python "…/schedule-interview/scripts/match_schedule.py" \
  --interviewer 张三 \
  --candidates "李四=8-3,王五=8-4" \
  --talent-ids "<李四tid>,<王五tid>" \
  --form 视频
```

| 参数 | 说明 |
|---|---|
| `--candidates` | `"姓名=时间,姓名=时间"`，时间语法见第 3 步；`@岗位方向` 展示用后缀；`#线下`/`#视频` 单人形式覆盖后缀（放最后，同面试官跨形式合并跑用） |
| `--talent-ids` | 与 --candidates 条目顺序对齐；不传则按姓名模糊匹配 ATS（同名歧义时告警） |
| `--form` | 视频（默认）/ 线下 |
| `--duration` | 每场分钟数，默认 45 |
| `--max-per-day` | 每天最多 N 场（批量排布防太密 → 2） |
| `--days` | 查询窗口天数，默认 7；候选窗口超 7 天必须显式传，否则静默剔尾日 |
| `--min-capacity` / `--room-name` / `--building` / `--floor` | 会议室约束（可选） |
| `--no-room` | 跳过会议室校验（纯远程/不需要会议室时） |
| `--team` | 团队名覆盖（默认取 ATS dept） |
| `--work-start` / `--work-end` | 工作时段（默认 9~18）；晚上面试有效传 `--work-end 21` |
| `--ats-file` | 临时 ATS 数据文件（见第 2 步） |
| `--dry-run` | 只验证解析 + ATS 匹配，不查飞书 |

其他场景：多面试官共同空闲 `--interviewer "张三,李四"`；单独看某面试官整周档期 `show_availability.py --interviewer 姓名`（日常约面不跑它，match 输出自带色块图）。

**Windows**：脚本绝对路径 + 正斜杠；`--candidates` / `--talent-ids` 含中文/逗号必须双引号包住整个值。

### 5. 交付

- **必交双格式**：emoji 色块图（match 输出自带段，🟩空闲/🟥会议/⬜午休/◽已过·周末，30分钟/格）**原样贴在草稿正上方** + markdown 表格（日期|空闲时段|45分钟档位）。表格看不出缺口是会议还是别的，色块图才行
- **草稿放代码块（```）里**：引用块/正文渲染会把多行挤成一行、复制丢换行层次；色块图和表格放代码块外
- 图的查询窗口与候选窗口天数一致；多面试官合并一张图（任一人忙即红）；色块 30 分钟粒度与精确档位可能差半小时，精确以【候选人匹配】段为准
- freebusy 是实时快照，隔几分钟查可能不同；转发前以最新一次查询为准
- 草稿含 `【需问用户】` → 问用户补齐后手改；用户说改时间 → 重跑脚本
- 脚本输出五段（忙碌/空闲/ATS/匹配/草稿+不可约）皆可溯源：忙碌段与飞书日历对不上 = 日程变了，重跑

## 草稿格式契约（脚本固化，AI 不改）

```
{称谓}，{团队}——{岗位}，{姓名}推进{轮次}，我和候选人沟通了一下面试时间：

{姓名}｜{岗位}·{轮次}
　可面时间：{完整窗口}
　拟安排：{M/D（周X）}{今天|明天}{上午|下午|晚上}N点[半|N点MM分]（{视频|线下}）

时间OK的话我直接和候选人敲定～
```

- 称谓 = interviewers.json 的 alias[0]，无 alias 用姓名；用户有惯用叫法 → 先写进 alias
- 轮次由 ATS（interview_count + latest_conclusion）推导：已面 N 轮且上轮通过 → 第 N+1 轮；不臆造
- 候选人块三行各自独立成行；可面时间、拟安排行首缩进一个全角空格
- 日期一律绝对日期；日期=运行日/次日时脚本自动补"今天/明天"标注
- 形式只出现在拟安排行，标题不放
- 可面时间：没说时段 → `全天（09:00-18:00）`；区间窗口原样（如 `14:00-15:00`）；相邻全天自动合并（`8/24（周一）~ 8/26（周三）`）
- 会议室：有可用 → 草稿完全不提；无可用 → 匹配结果标 ❌ 提示换时段
- 多候选人：按拟安排时间排序，每人一块，一条草稿发

## AI 纪律

**做**：
- 同一面试官面多人 → 一次跑、一条草稿（`--candidates "A=时间,B=时间"`；跨形式用 `#线下`/`#视频` 后缀）
- 批量排布密度：每场 45 分钟、每天 ≤2 场、上午最多 1 场、场间 ≥2h（`--max-per-day 2`）；场次多时别堆同一面试官，灵活候选人可转 HR 面分流
- 用户一次给的候选人跨面试官/跨岗位 → 按"面试官+岗位"分组多次调用

**不做**：
- 不临场改草稿措辞（不加客套、不加面评、不换格式；用户说调才调）
- 不把候选人原话口语塞进草稿
- 不堆前序面试官名单（轮次标签已隐含通过前几轮）
- 不把同一面试官拆成多条草稿
- 不替用户发 IM / 飞书招聘建面试 / 问候选人时间 / 预订会议室（本 skill 只查可用，不预订）
- 不写多维表格（跟踪表已退役，一切以 ATS 为准）
