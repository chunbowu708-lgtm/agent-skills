# 面试时间协调

## 你要做什么（30 秒版）

```
用户给：面试官 + 候选人 + 候选人可面试时间
你跑：  match_schedule.py → 脚本自动查面试官空闲 ∩ 候选时间 → 算交集 → 查会议室 → 出可转发草稿
你交付：把"匹配结果 + 草稿"展示给用户，用户扫一眼转发
```

**AI 的职责只有两件事**：
1. **把用户自然语言无损转成脚本参数**（重点：候选时间转绝对日期、查 talent_id、确认 form）
2. **处理脚本明确标注的 `【需问用户：XXX】` 缺口**

其余全是脚本自动，**不临场改草稿措辞**。

## 执行路径（按顺序做）

### 第 1 步：明确三要素（缺一不许跑）

| 要素 | 来源 | 缺了怎么办 |
|------|------|-----------|
| 面试官姓名 | 用户口头 | ❌ 问用户，不许猜 |
| 候选人（姓名 + 可面试时间） | 用户口头 | ❌ 问用户，不许猜 |
| 形式 | 默认视频，用户没说就传 `--form 视频` | 用户说"线下"才传 `--form 线下`（`--form 现场` 仍兼容，自动归一化为"线下"） |

### 第 2 步：查候选人 talent_id（精确匹配 ATS）

从 `<PROJECT_ROOT>/notes/_daily_review.json` 的 `structured.ats[*]` 按姓名查，传给 `--talent-ids`（与 `--candidates` 顺序对齐）。查不到就按姓名模糊匹配（同名歧义时脚本会告警）。

### 第 3 步：候选时间转绝对日期（⚠️ 最关键，约错时间就是这里）

**能确定语境就给绝对日期（`8-3`），不要丢模糊词给脚本猜。**

- 今天是周一，候选人说"周一周二" = 今天+明天 → 传 `8-3,8-4`
- 脚本对"周X"默认取未来最近那天：今天周一传"周一"会被解析成下周一（8/10）！
- ⚠️ **剔除已过的日期/时段**：脚本按整天算空闲，不知道"现在几点"——候选人说"这周都可以"且现在已是下午，今天上午的时段虽空闲但已错过，**传参时从明天起**（`8-4|8-5` → 传 `8-5|8-6`），否则草稿"拟安排"会落在过去时段（8/4 下午跑脚本，草稿出"8/4 上午 11 点"这种废稿）
- ⚠️⚠️ **"面试可以时间"（窗口）≠"拟安排"（建议），永不混（2026-08-04 用户明确纠正）**：
  - **窗口 = 候选人完整可约时间，必须忠实原话**："这周都可以" → 传 `8-5|8-6|8-7`（完整 3 天，草稿"面试可以时间"照展示，面试官可自选）
  - **拟安排 = 建议时段**，可按优化目标调（集中某天/黄金时段）——靠 candidates 顺序 + hint + 同名条目拆分控制 hits[0]
  - ❌ **禁止为集中排布而压缩窗口**：把"这周都可以"传成 `8-5` 只为了让拟安排落周三，是拿拟安排意图偷换可约窗口——面试官失去自选空间、候选窗口失真，用户会直接怼回来
  - 正确姿势：窗口原话完整传，拟安排偏好用条目顺序表达（"多安排周三" → 窗口仍是 8-5|8-6|8-7，拟安排自然落周三）

### 第 4 步：跑脚本（见下方标准命令）

### 第 5 步：展示结果

- **面试官可约时段 = 必交项，且必须是图示化（SVG 色段图）+ 表格双格式（2026-08-06 用户定稿："直接图示化面试官可约时段，不要靠记忆，要靠流程"）**：每批草稿交付时，对涉及的每位面试官跑 `show_availability.py --svg <path>`，把生成的色段图内联渲染给用户（绿=空闲/红=会议/灰=午休/半透明=已过·周末），同时附 markdown 表格（日期|空闲时段|备注 + 45分钟档位）——用户需要一眼看到"啥时候有会议/其他事"，表格只能反推缺口，看不出忙碌原因
  - ⚠️ **纯表格不够**：2026-08-06 用户明确反馈"我看不出他啥时候有会议或者其他事，不是说用SVG色段图"——空闲时段表只能看到缺口，SVG 色块图才能直接看到红块=会议在哪。**SVG 是主交付格式，表格是补充**
  - 查询窗口：与本次草稿的候选窗口对齐（match 用了几天就查几天），多人面试官逐一展示
  - 渲染方式：读 SVG 文件内容后内联渲染（可视化面板），文件留存在 `notes/avail_<姓名>.svg` 供复看
  - **freebusy 实时性提醒**：SVG 是查询时点的快照，同一区间隔几分钟查可能不同（实测 8/6 钟惟鸿 17:24 查 2 段会议 vs 当天下午 match 时 0 段）。拟安排落点在绿块内就安全，转发前以最新一次查询为准
- 把"匹配结果 + 草稿 + 面试官可约时段表 + SVG 色段图"都展示给用户，让用户扫一眼能不能直接转发
- 草稿里有 `【需问用户：XXX】` → 问用户补齐后手改草稿
- 草稿是建议，用户可改。用户说"改到周五"→ 重跑脚本

## 标准命令

```bash
# ⭐ 展示面试官本周可约时段（45分钟/场切档，默认只列未来档位）——**每批草稿交付必跑**（2026-08-06 升级：从可选项改为必交项，见第 5 步）
#    输出 = ①markdown表格（日期|空闲时段|备注，自动生成"最宽裕/较宽裕/时段零碎/周末"）②45分钟档位列表
python ".../show_availability.py" --interviewer 古振兴
python ".../show_availability.py" --interviewer 古振兴 --svg avail.svg   # ③生成时间轴色段图（绿=空闲/红=会议/灰=午休/半透明=已过·周末），拿到后用可视化渲染给用户
python ".../show_availability.py" --interviewer 谢坤,潘腾飞 --duration 60   # 多人：每人+共同档位
python ".../show_availability.py" --interviewer 古振兴 --start 2026-08-05 --days 3
python ".../show_availability.py" --interviewer 古振兴 --work-start 10:00 --work-end 20:00  # 晚上面试

# ⭐ 推荐：传 talent_ids 让脚本精确匹配 ATS，出完整草稿（时长默认 45，需要 60 显式传 --duration 60）
python "…/schedule-interview/scripts/match_schedule.py" \
  --interviewer 谢坤 \
  --candidates "范晶昌=8-3,汤娟=8-4" \
  --talent-ids "7664545205329381651,7663322896458549558" \
  --form 视频

# 不传 talent_ids（按姓名模糊匹配 ATS，同名歧义时脚本告警）
python ".../match_schedule.py" --interviewer 谢坤 --candidates "罗艺=8-3" --duration 60

# 多面试官（取共同空闲）
python ".../match_schedule.py" --interviewer "谢坤,潘腾飞" --candidates "张三=8-3" --duration 60

# 会议室容量约束（视频/线下默认都查会议室）
python ".../match_schedule.py" --interviewer 王长江 --candidates "何明杰=8-4" --form 线下 --min-capacity 3 --duration 60

# 纯远程/不需要会议室 → --no-room 跳过会议室校验
python ".../match_schedule.py" --interviewer 谢坤 --candidates "罗艺=8-3" --form 视频 --no-room --duration 60

# 先 dry-run 验证 ATS 匹配（不查飞书）
python ".../match_schedule.py" --interviewer 谢坤 --candidates "..." --talent-ids "..." --dry-run
```

**参数说明**：
- `--candidates "姓名=时间,姓名=时间"`：候选人及可面试时间。时间用**绝对日期**（`8-3`）最稳，也支持 `周四/明天/周四下午`（草稿输出自动转绝对日期）
- **多日期用 `|` 分隔**：`"何明杰=8-4|8-5"`（逗号已被 --candidates 用于分隔候选人）——草稿"面试可以时间"会展示完整可约窗口，面试官可自选
- **复杂时段窗口（"明天上午+工作日下午都可以"这类）= 同名多条目拆分**：`--candidates "何明杰=8-5上午,何明杰=8-5下午|8-6下午|8-7下午"`（talent-ids 对应传两次同值）。脚本按 name 聚合 hits，**hits[0]=拟安排，偏好的条目放最前**。⚠️ 局限：窗口文本的时段偏好（time_pref）按最后一条覆盖，可能标"（下午）"而拟安排在上午——转发前向用户说明真实窗口即可
- `--talent-ids`：与 `--candidates` 顺序对齐，精确匹配 ATS
- `--form 视频|线下`：面试形式，默认视频（`--form 现场` 仍兼容，自动归一化为"线下"）
- `--min-capacity N`：会议室最小容量（默认 0=不限制）
- `--no-room`：跳过会议室校验（默认**视频/线下都查**——业务面试官视频面试也在公司会议室里）
- `--room-name / --building / --floor`：会议室名称/楼栋/楼层约束（可选）
- `--team`：团队名覆盖（默认取 ATS dept）
- `--work-end 21`：晚上面试有效时扩展工作时段
- `--max-per-day N`：**每天最多 N 场**（0=不限）。用户"别排太密"偏好落地——每天 ≤2 场、上午最多 1 场时传 `--max-per-day 2`。密度只按每个候选人的**拟安排落点**计数（同名条目的兜底备选日期不计），某天满了候选人自动顺延后续日期，草稿窗口如实剔除满员日期

**Windows 铁律**：脚本路径绝对路径 + 正斜杠。`--candidates` / `--talent-ids` 含中文/逗号，**必须双引号包住整个值**。


**读法**：忙碌段对不上飞书日历 → 日程变了，重跑。草稿直接展示给用户。

**格式要点**（脚本固化，AI 不改）：
- 团队岗位用"——"间隔："长青工作室——3D场景设计师"，不连写
- 多人岗位相同 → 标题合并写一个岗位；**岗位不同 → 标题只写团队，岗位跟人名走**："张志龙（3D角色设计师·复试）"
- 候选人块 = 姓名（岗位·轮次）→ 面试可以时间（完整窗口）→ 拟安排（最优+形式）。**会议室信息不展示**——有会议室时不提，只在某时段全无可用会议室时才告警提示换时段（2026-08-04 用户定稿）
- 拟安排必须标形式："下午2点（视频）" / "上午11点（线下）"
- 面试可以时间：单日且没说时段 → 标"全天"；有时段偏好 → 附加（下午）

## AI 介入点（全部情况，诚实版）

### 日常三件（每次跑必做，算"正确传参"不算"介入"）

1. 从 `_daily_review.json` 查候选人 talent_id 传给脚本
2. 候选时间转绝对日期传参（见执行路径第 3 步）——**窗口完整、拟安排靠顺序**，两件事分开控制
3. 确认形式：用户说"线下"→ `--form 线下`，否则默认视频

### 排布密度（用户偏好，2026-08-04 确立）

- **面试时长 45 分钟/场**（用户定稿），跑脚本传 `--duration 45`
- **别排太密**：多候选人批量排时避免同一天堆太多场、上午连轴。用户明确"别太密"→ 每天 ≤2 场、上午最多 1 场、场间 ≥2h
- "多安排某天"（如周三最宽裕就集中排）是**拟安排层面**的诉求，靠传参顺序控制拟安排落点，**不压缩候选窗口**（见第 3 步窗口 vs 拟安排）
- 面试官有惯用昵称（如 Sava=古振兴）→ `interviewers.json` 加 `alias`，草稿称谓自动用 alias[0]（用户平时怎么叫就怎么写）

### 异常两件（脚本标了才做）

1. **`【需问用户：岗位/上轮进展/轮次】`**：ATS 没匹配到该候选人。问用户拿信息后手改草稿
2. **信息分组/岗位归属重组**：用户一次给的候选人跨岗位/跨面试官（如"彭亦翔郭图博是 Sava 面 UGC策划，黄雷也是 Sava 面产品经理"）。拆成"按面试官+岗位分组"的多组脚本调用

### ❌ 永不做的（踩坑血泪，做了就废）

- **不临场改草稿措辞**：脚本草稿已对齐自然口语。AI 不加客套、不加面评名单、不换格式。用户说措辞要调才调
- **不把候选人原话塞进草稿**：脚本输出规整后的"面试可以时间：周二"，不还原"那就周二吧～"这类口语
- **不堆前序面试官名单**：轮次标签（三面）已隐含通过前两轮，面试官名字对约面决策无帮助

## 约束模型（背景理解，不是执行路径）

> 所有规则都能归位到三层。想不通一条规则为什么存在，回这层找。

```
排程问题 = 输入约束求交 + 输出契约达标
  ├─ L1 输入硬约束：候选时间 / 面试官空闲(含防撞档) / 时长 / 场地(会议室)
  ├─ L2 输入软约束：黄金时段 / 候选人偏好时刻
  └─ L3 输出契约：自包含 / 绝对日期 / 待确认措辞 / 形式显式 / 会议室措辞诚实
```

### L1 输入硬约束（不可违反，违反=废稿）

| 约束 | 说明 | 脚本处理 | 备注 |
|------|------|---------|------|
| 候选时间 | 在候选人能来的窗口里找时段，**不能反过来**（面试官中心论是新人最常犯的错） | `intersect()` | AI 传参用绝对日期（见执行路径第3步） |
| 面试官空闲 | freebusy 真实忙碌反推空闲（suggestion 漏报已弃用） | `get_freebusy_blocks()` | — |
| **防撞档** | 同一面试官同一时段不能分给两人（是"空闲"的直接推论） | `_has_conflict()` + `occupied` | 单次调用内有效；草稿是待确认建议，面试官点头后建日历事件，freebusy 自然挡后续撞档 |
| 时长 | 45 分钟/场（2026-08-04 用户定稿；按需传 `--duration 60` 等） | `--duration` | 默认 45，显式传参覆盖 |
| **场地（会议室）** | **视频/线下都要**——业务面试官视频面试也在公司会议室里。黄金时段没会议室→顺延到有会议室的可约时段；全时段没会议室→该日期标❌告警、建议换日期。**全量校验**：`vc/v1/rooms` 枚举全部会议室 + `freebusy/list` 逐间查忙闲（不用 room-find 推荐子集，实测漏报 5/7 间） | `find_rooms()` + `--min-capacity`/`--no-room` | ⚠️ **会议室是"校验器"，成功时静默失败时告警**（2026-08-04 用户定稿）：有会议室→草稿不提会议室（不写"共N间可用"、不写"已查到可用"）；无可用会议室→才在匹配结果标❌提示换时段。查询不是"预订" |

### L2 输入软约束（优化目标，不违反 L1 前提下追求）

| 约束 | 说明 | 脚本处理 |
|------|------|---------|
| 黄金时段 | 11:00、15:00-18:00 优先；避开 09:00 过早 / 午休 / 18:00+ 偏晚 | `_slot_priority()` |
| 候选人偏好时刻 | 候选人给了精确时刻（"周四 16:00"）→ 优先贴他给的时间点 | `best_slot()` |

### L3 输出契约（消息品质，违反=消息废掉）

| 契约 | 说明 | 谁保证 |
|------|------|--------|
| 自包含（五要素） | 岗位、候选人、哪轮/角色、形式、时间——面试官收到消息不能有任何追问 | 脚本吃 ATS 出完整草稿 |
| 绝对日期禁相对词 | 草稿不许出现"明天/后天/周四/下周三"——面试官收到时可能已不是发消息那天 | `_candidate_block` 用 hits 的绝对日期（wd+date_str）直接生成 |
| 待确认措辞 | "拟安排/可以吗"，不是"已安排" | 脚本固化 |
| 形式显式出现 | 默认视频但必须写出来——面试官要知道准备什么 | `--form` + 草稿结尾 |
| 会议室成功时静默 | 有可用会议室→草稿**完全不提**会议室（不写推荐间名、不写"共N间可用"、不写"已查到可用"）；只有某时段全无可用会议室→才告警提示换时段（2026-08-04 用户定稿：成功时提会议室 = 噪音） | 脚本固化 |
| AI 不改稿 | 草稿直接展示，用户说调才调 | AI 纪律（见 AI 介入点） |

## 标准输入（用户这样跟我说即可）

```
面试官：谢坤（可多人，逗号分隔）
候选人时间：
  罗艺 - 周四
  陈思宇 - 周四
  刘涵辰 - 周五
（可选）面试时长：60分钟
（可选）面试形式：视频 / 线下（默认视频）
```

候选人时间支持的写法（输入层可任意相对/模糊，草稿输出统一转绝对日期）：
- `周四` / `周五` — 模糊日（默认未来最近那天）
- `周三下午` / `周四晚上` — 日 + 时段偏好
- `周四 16:00` — 精确时刻
- `7-3` / `7月3日` — 绝对日期
- `今天` / `明天` / `后天` — 相对日
- `下周三` / `这周五` — 带前缀的星期词
- `8-4|8-5` / `周一周二` — **多日期**（`|` 分隔；"周一周二"连续星期词自动拆）——草稿"面试可以时间"展示完整窗口，面试官可自选

> ⚠️ **AI 转译提醒（最重要）**：能确定语境就给绝对日期（`8-3`）。今天周一候选人说"周一周二"=今天+明天，传 `8-3,8-4`；丢"周一"给脚本会被解析成下周一（8/10）。
