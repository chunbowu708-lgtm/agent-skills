# 决策记录（规则为什么是这样）

> 维护者参考，不是执行路径。Agent 日常执行只看 SKILL.md。本文件记录 SKILL.md 每条规则背后的设计约束，供修改/审查时理解决策依据。
>
> 仅记结论性约束（什么/为什么不），不含时间戳、案例叙事。历史沿革见 CHANGELOG。

---

## 录入是原子操作（一条命令完成）

录入 = 录人才 → 建投递 → 建跟踪表行 → 三段校验，全部内联进 `_hire.py`，一条命令自动串完。track/verify 改为转发器（逻辑在 `_hire.py`），单独调用仅调试用。
- 约束：可确定的流程交给脚本，不让 AI 临时编排多步工序。中间文件 `_hire_result.json` 降级为日志，不再是流程必经契约。

## 岗位准入闸门：必须「我创建 + 开放中」

录入目标岗必须同时满足「我创建 + active_status=1」。`_hire.py` 内置 `job_filter_ok()` 自动校验，即使直接传编号也会校验状态+归属。
- 约束：飞书招聘里暂停/已关闭的岗删不掉（产品限制），只能靠准入过滤而非手工避让。永远用岗位关键词让脚本自动选，不手撸 jobs API。

## 存量 talent 旧简历残留风险

录入复用存量 talent（邮箱/手机命中已有 talent）时，旧简历附件还挂在档案上，投递会自动挂旧附件（可能含过时信息或薪酬）。
- `_hire.py` 录入后自动检测旧附件，有则告警。
- 飞书 API 不支持删旧附件（无 delete 接口；combined_update 只追加不替换主附件）→ 必须提示用户去飞书招聘后台手动删。
- 投递绑旧附件时：`swap_resume.py` 做 terminate 旧投递 + 重建（飞书自动绑最新上传附件），仅限早期阶段。

## 淘汰接口：terminate 是唯一正确路径

飞书招聘的淘汰**不是** transfer_stage（job_processes 流程里只有 type 1-7 正常阶段，无淘汰阶段），也**不是** PUT /applications/:id 改字段（该接口 404）。
- 唯一正确接口：`POST /hire/v1/applications/:id/terminate`，请求体 `{"termination_type":<int>}`，调后 active_status 变 2。
- 接口完整契约在 lark-hire skill，本条只记"为什么是 terminate 而非其他"。

## _my_jobs.json 是会过期的快照

对账脚本按 `_my_jobs.json`（我创建的岗位 job_id 快照）过滤投递。新创建的岗位不在快照里 → 该岗投递被过滤 → 候选人漏报。
- 约束：岗位增减后必须跑 `refresh_my_jobs.py` 刷新（page_size≤20 全量翻页，>20 返回空）。任何"快照缓存"都不能当真相源。

## 消息意图判读：不用关键词，交给 LLM

意图判读是语义判断（上下文相关），交主会话 LLM 做，禁止关键词匹配。
- 反例佐证约束成立："安排不太合适"含"安排"但是反对；"需要hr帮忙面一轮"无邀约词但是真邀约。字符串匹配在语义场景必然失效。

## raw_messages 不截断

群消息/私聊原文全量导出，不按长度截断。含多个候选人的长消息被腰斩后拆句判读失效。

## 跟踪表分层共管（字段写权三分）

字段分三层，每层只有一个写权方（详细字段表 + ATS→表映射见 review-contract.md）：
- 客观层（状态/轮次/面试时间/进入阶段日期）：只归 `_daily_review.py --write`
- 主观层（下一步动作/优先级/备注/面试官）：归人工
- 主键层 talent_id：归 `_hire.py`（录入时自动写）。存量回填是一次性历史任务，已完成。
- 约束：多写权方共存 = 数据必然漂移。ATS 是唯一事实源，分层是正确性约束不是风格偏好。

## 接棒保温必须强制（step 6）

作战清单（今天处理谁）和保温清单（今天碰谁）是同一个早晨决策流的两半。作战清单输出、用户确认决策后，Agent 必须主动继续执行 candidate-nurture，不需用户重新喊"保温"。
- 约束：两个 skill 串行耦合时，"接棒"必须是硬指令而非软建议，否则后半场永远不被触发。

## 表格自动同步

跟踪表客观层由每晚 18:30 计划任务 `MiniwaRecruitDailySync` 跑 `_sync_tables.py` 全量从 ATS 同步（主观层只填空槽）。早晨 Agent 读到的表格已是最新，但仍需重跑对账拿 18:30 后的消息和当天面试结果。
